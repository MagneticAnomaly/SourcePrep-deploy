## What is CoDRAG?

CoDRAG (Code Documentation and RAG) is a local-first codebase intelligence platform. It builds persistent semantic indexes of codebases and serves bounded, source-cited context to AI coding agents via MCP (Model Context Protocol). The goal is to give AI agents robust contextual and epistemological knowledge of a codebase — far beyond what static files or grep can provide. It supports Cursor, Windsurf, Claude Code, VS Code, Gemini CLI, Qwen Code, and GitHub Copilot.

## Architecture

Three-language monorepo: Python backend, Rust performance engine, TypeScript frontends.

### Python Backend (`src/codrag/`)

- **Entry points:** `cli.py` (Typer CLI), `server.py` (FastAPI on :8400), `mcp_direct.py` (MCP server)
- **`core/`** — Core engine: indexing, embeddings, file watching, LLM coordination, trace graph, audit system, atlas generation
- **`services/`** — Higher-level orchestration: build pipeline, embedder, augmenter, epistemic enrichment
- **`api/routers/`** — FastAPI routes: projects, search, context, trace, LLM, build, audit, pipeline, roadmap
- **`adapters/`** — Integration adapters
- **`mcp/`** — MCP protocol implementation; `mcp_tools.py` defines all MCP tool handlers
- **`dashboard/`** — React dashboard app (lives inside Python package but is a separate npm workspace)

### Rust Engine (`engine/crates/`)

Called from Python via `maturin` bindings. Workspace crates:
- **codrag-engine** — Main orchestrator
- **codrag-walker** — File system traversal
- **codrag-parser** — AST parsing via tree-sitter (Python, TypeScript)
- **codrag-graph** — Symbol graph building (nodes, edges, import chains)
- **codrag-chunking** — Code segmentation for embeddings
- **codrag-sanitize** — Content filtering
- **codrag-selfheal** — Error recovery

### Frontend (`packages/`, `src/codrag/dashboard/`, `websites/`)

npm workspaces managed by Turbo:
- **`packages/ui`** — Shared React component library (`@codrag/ui`). Tailwind + Radix UI + Tremor charts. Storybook for design system docs.
- **`src/codrag/dashboard`** — Main dashboard app (React/Vite, optional Tauri wrapper). Connects to daemon API at :8400.
- **`packages/vscode`** — VS Code extension with webview UI
- **`websites/apps/*`** — Marketing and docs sites (Next.js)

### Data Flow

1. **Indexing:** Rust engine parses files (tree-sitter) into a structural graph → Python enriches with embeddings (ONNX native or Ollama) and optional LLM augmentation (multi-pass pipeline)
2. **Storage:** SQLite for project registry, JSON files + numpy arrays for indexes. Standalone mode in `~/.local/share/codrag/projects/`, embedded mode in `.codrag/` (git-trackable)
3. **Serving:** FastAPI daemon exposes search/context/trace APIs. MCP server wraps these for IDE consumption. Dashboard talks to the same HTTP API.

## CoDRAG MCP Tools (Use These)

This project ships its own MCP server. See AGENTS.md for tool-calling details and the current project_id. When the CoDRAG daemon is running, these tools are available and **should be actively used during development**:

- `codrag` — Call at the start of every task. Returns structural overview: module map, hub files, focus areas, cross-cutting concerns. This is your primary orientation tool.
- `codrag_search` — Semantic code search. Prefer this over grep when you need to understand how code connects structurally, not just find a string match.
- `codrag_impact` — Dependency impact analysis. Call before modifying files with many dependents to understand blast radius.
- `codrag_audit` — Codebase health and tech debt analysis.
- `codrag_observe` — Cross-session memory and notes.

All CoDRAG tools are read-only and safe to auto-approve. They complement (not replace) direct file reads, grep, and git — use the right tool for the job. CoDRAG excels at structural relationships and semantic intent; grep excels at exact string matching.

**Dogfooding note:** Every call to these tools is also a test of the product. If results are unhelpful, incomplete, or wrong, that is actionable product feedback — mention it.

## MCP Server Modes

CoDRAG has two MCP server implementations. Understanding the difference prevents confusion:

- **Server mode** (`src/codrag/mcp/server.py`, default) — Proxies to the running daemon at :8400. Full-featured: multi-project support, ambient context (atlas, hub files, modules), all 5 tools + aliases, adaptive context budgets per client, role-based atlas projection. **Use this when the daemon is running.**
- **Direct mode** (`src/codrag/mcp_direct.py`, `--mode direct`) — Runs CodeIndex/TraceIndex in-process, no daemon required. Simpler single-project setup but has drifted behind server mode. The `codrag` no-arg ambient context call is broken in direct mode (routes to search-context which requires a query). Only handles a subset of tools.

The wrapper script (`codrag-mcp-wrapper.sh`) and `.claude/mcp.json` / `.cursor/mcp.json` should default to server mode. Direct mode is a valid feature (daemon-free MCP) but needs parity work to match server mode's tool dispatch.

## How CoDRAG Generates AGENTS.md for Client Projects

A core CoDRAG feature is generating AGENTS.md files that tell AI agents about the MCP tools available to them. Understanding this pipeline is essential when working on the product.

### Generation Pipeline

1. **`src/codrag/core/rules_generator.py`** — Main orchestrator. `write_rules_file()` detects target IDEs and dispatches to per-IDE writers. `_build_managed_content()` generates the unified content block shared across all targets (Cursor, Windsurf, Claude Code, Copilot, etc.).
2. **`_write_agents_md()`** (rules_generator.py:760) — Writes to `AGENTS.md` at the client project root. Uses `<!-- codrag-managed-start/end -->` markers to splice managed content while preserving user additions.
3. **`src/codrag/mcp_tools.py`** — Defines the 5 core MCP tool schemas (name, description, parameters, annotations). These are served via `mcp/server.py` `handle_tools_list()` and are the source of truth for what tools exist.
4. **`src/codrag/core/atlas/`** — Generates the "Codebase Atlas" section: project identity, stack summary, workspace map, cross-cutting concerns, hub files.

### What Goes Into a Generated AGENTS.md

- **Tool calling instructions** — Hardcoded in `_build_managed_content()`. Tells agents to call `codrag` immediately, routes via `project_id`, maps user intents to tool calls.
- **Codebase Atlas** — Auto-generated structural snapshot: identity, stack, workspace segments, hub files, entry points, import cycles.
- **Focus Areas** — User-selected paths for priority context.
- **Refresh hints** — When to re-call `codrag` during long tasks.

### Design Intent

The generated AGENTS.md is meant to be the first thing an AI agent reads when it opens a client project. It declares: "You have an MCP tool — use it to get live structural context beyond what any static file can provide." The tool instructions are front-loaded and aggressive ("IMMEDIATELY call", "No announcements") because the biggest failure mode is agents ignoring the MCP tools and falling back to grep/file reads for everything.
