# Phase 49: Process Metadata & Data Provenance — Implementation Plan

## Overview

Build a comprehensive process metadata tracking system that captures:
- Which models were used for each pipeline stage
- When data was last generated
- Quality metrics for each run
- Version information (CoDRAG, engine, models)
- File-level provenance (hashes, timestamps)

This enables users to:
- Trust their data ("This was generated by qwen3:14b 4 months ago")
- Debug issues ("Why is this summary wrong?" → check which model/version)
- Identify stale data ("This index is 6 months old, should I rebuild?")
- Compare model quality ("Model A had 0.87 avg confidence, Model B has 0.92")
- Eventually purge old/low-quality data

**Goal:** Capture model info, timing, and quality metrics in existing manifest files

**Files to Modify:**

2. `src/codrag/core/epistemic_enrichment.py` — `EpistemicEnrichment.run()`

**New Dataclass:**
```python
@dataclass
class StageManifest:
    """Enhanced manifest for a pipeline stage."""
    format_version: str = "2.0"
    stage_id: str = ""
    run_id: Optional[str] = None
    project_id: Optional[str] = None
    
    # Provenance
    codrag_version: str = ""
    engine_version: Optional[str] = None
    engine_backend: str = "python"  # "python" | "rust"
    
    # Model Info
    model: Optional[Dict[str, Any]] = None  # task_id, provider, endpoint_id, model_name, etc.
    embedding_model: Optional[Dict[str, Any]] = None  # for knowledge index
    
    # Timing
    started_at: Optional[str] = None  # ISO timestamp
    finished_at: Optional[str] = None
    elapsed_seconds: Optional[float] = None
    
    # Quality Metrics
    quality: Optional[Dict[str, Any]] = None  # total_items, processed, success_rate, avg_confidence, etc.
    
    # File Provenance
    input_files: Optional[Dict[str, Dict[str, Any]]] = None  # filename → {size_bytes, hash, item_count}
    output_files: Optional[Dict[str, Dict[str, Any]]] = None
    
    # Performance
    throughput: Optional[Dict[str, float]] = None  # items_per_second, bytes_per_second
    
    # Errors
    errors: Optional[List[Dict[str, str]]] = None  # [{node_id, error, detail}]
```

**Implementation Steps:**

1. Create `src/codrag/core/stage_manifest.py`:
   - `StageManifest` dataclass

   - `compute_file_hash()` — blake3 hash of a file

   - `aggregate_quality_metrics()` — compute avg/min/max from JSONL entries

3. Update each worker class:
   - Add `run_id` parameter to `run()` method
   - Capture start timestamp
   - Capture model info from LLM client
   - Run existing logic
   - Capture end timestamp
   - Aggregate quality metrics from output JSONL
   - Create and save `StageManifest`
   - Write to manifest file (e.g., `trace_augment_manifest.json`)

**Effort:** ~8-12 hours

### Phase 2: Run-Level Metadata File ✅ READY TO BUILD

**Goal:** Create `pipeline_run_metadata.json` with run-level aggregates

**New Dataclass:**
```python
@dataclass
class PipelineRunMetadata:
    """Metadata for an entire pipeline run (fast_sync or deep_enrichment)."""
    run_id: str
    project_id: str
    group: str  # "fast_sync" | "deep_enrichment"
    
    # Provenance
    codrag_version: str
    engine_version: Optional[str] = None
    engine_backend: str = "python"
    
    # Timing
    started_at: str  # ISO timestamp
    finished_at: Optional[str] = None
    elapsed_seconds: Optional[float] = None
    
    # Stages
    stages: List[Dict[str, Any]] = field(default_factory=list)
    # Each stage: {stage_id, started_at, finished_at, elapsed_seconds, status, model, manifest_file}
    
    # Overall Quality
    quality_summary: Optional[Dict[str, Any]] = None
    # {total_files_processed, avg_confidence, staleness_ratio, coverage_ratio}
    
    # Models Used
    models_used: Dict[str, Dict[str, Any]] = field(default_factory=dict)
    # task_id → {provider, model, endpoint_id}
    
    # Configuration Snapshot
    config_snapshot: Optional[Dict[str, Any]] = None
    # {batch_mode, assignment_mode, max_active_projects, etc.}
```

**Files to Modify:**
1. `src/codrag/services/pipeline/orchestrator.py`:
   - `_start_group()` — create `PipelineRunMetadata`, write initial file
   - `_on_build_transition()` — update metadata file after each stage completes
   - `_advance_pipeline()` — finalize metadata file on completion

**Implementation Steps:**

1. Create `src/codrag/services/pipeline_metadata.py`:
   - `PipelineRunMetadata` dataclass
   - `create_run_metadata()` helper
   - `update_run_metadata()` helper (add stage info)
   - `finalize_run_metadata()` helper (aggregate quality, compute summary)
   - `save_run_metadata()` helper
   - `load_run_metadata()` helper

2. Update `PipelineOrchestrator`:
   - In `_start_group()`:
     - Create `PipelineRunMetadata` with run_id, project_id, group
     - Capture CoDRAG version, engine version
     - Capture config snapshot
     - Write to `<index_dir>/pipeline_run_metadata.json`
   
   - In `_on_build_transition()` (when stage completes):
     - Load stage manifest (e.g., `trace_augment_manifest.json`)
     - Extract stage info (timing, model, status)
     - Update `PipelineRunMetadata.stages` list
     - Update `PipelineRunMetadata.models_used` dict
     - Write updated metadata file
   
   - In `_advance_pipeline()` (when all stages done):
     - Load all stage manifests
     - Aggregate quality metrics across stages
     - Compute quality_summary
     - Set finished_at, elapsed_seconds
     - Write final metadata file

**Effort:** ~6-8 hours

**Testing:**
- Unit tests for `PipelineRunMetadata` serialization
- Integration test: run fast_sync, verify metadata file created
- Integration test: verify metadata file updated after each stage
- Integration test: verify final metadata has quality_summary

### Phase 3: Historical Run Registry ✅ READY TO BUILD

**Goal:** SQLite table for fast queries across all historical runs

**New Table:**
```sql
CREATE TABLE pipeline_run_history (
    run_id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    group_name TEXT NOT NULL,
    status TEXT NOT NULL,
    started_at REAL NOT NULL,
    finished_at REAL,
    elapsed_seconds REAL,
    codrag_version TEXT,
    engine_backend TEXT,
    
    -- Aggregated quality metrics (JSON)
    quality_summary TEXT,
    
    -- Models used (JSON)
    models_used TEXT,
    
    -- Stage count
    total_stages INTEGER,
    completed_stages INTEGER,
    failed_stages INTEGER,
    
    -- File reference
    metadata_file TEXT,  -- path to pipeline_run_metadata.json
    
    created_at REAL NOT NULL
);

CREATE INDEX idx_run_history_project ON pipeline_run_history (project_id, started_at DESC);
CREATE INDEX idx_run_history_status ON pipeline_run_history (status);
CREATE INDEX idx_run_history_version ON pipeline_run_history (codrag_version);
```

**Files to Create:**
1. `src/codrag/services/pipeline_history.py`:
   - `PipelineRunHistory` service class
   - `init(db_path)` — create table if not exists
   - `record_run(metadata)` — insert row from `PipelineRunMetadata`
   - `get_project_runs(project_id, limit)` — list recent runs
   - `get_run(run_id)` — get single run
   - `get_runs_by_model(model_name)` — find runs using specific model
   - `get_runs_by_quality(min_quality)` — find high/low quality runs
   - `get_runs_by_version(codrag_version)` — find runs from specific version

**Files to Modify:**
1. `src/codrag/services/pipeline/orchestrator.py`:
   - In `_advance_pipeline()` (on completion):
     - Load final `PipelineRunMetadata`
     - Call `pipeline_history.record_run(metadata)`

2. `src/codrag/server.py`:
   - Initialize `pipeline_history` on startup (after journal init)

**Implementation Steps:**

1. Create `PipelineRunHistory` service class
2. Add table creation to `init()`
3. Implement `record_run()` to insert from metadata
4. Implement query methods
5. Wire into orchestrator

**Effort:** ~6-8 hours

## Risk Mitigation

### Risk: Performance Impact
**Mitigation:** Write metadata files async, don't block pipeline execution

### Risk: Backward Compatibility
**Mitigation:** Handle missing manifest files gracefully, show "unknown" for old data

### Risk: Storage Growth
**Mitigation:** Implement retention policy (keep last N runs per project)

### Risk: Complexity
**Mitigation:** Start with Phase 1 only, validate with users before building UI
