# Phase 49: Process Metadata & Data Provenance

## Overview

Comprehensive process metadata tracking system that captures full provenance for all pipeline runs:
- **Model Provenance**: Which LLM/embedding model was used for each stage
- **Version Tracking**: CoDRAG version, engine version, model versions
- **Quality Metrics**: Confidence scores, success rates, parse errors
- **Timing Data**: Per-stage and per-run timing information
- **File Provenance**: Input/output file hashes and metadata
- **Performance Metrics**: Throughput, items/second

## Problem Statement

Users need to know:
- "This summary was generated by qwen3:14b 4 months ago" (trust & transparency)
- "Why is this file's summary wrong?" → Check which model/version produced it (debugging)
- "Is my data up to date?" → Check last run timestamp and file hashes (staleness detection)
- "Which model produces better results?" → Compare quality metrics (model selection)

Without this metadata, users have no visibility into:
- Data age and staleness
- Which models produced which data
- Quality of their index
- Whether they should rebuild

## Solution Architecture

### 3-Layer Metadata System

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: Stage Manifests (Per-Stage Metadata)              │
│ - trace_augment_manifest.json                              │
│ - trace_epistemic_manifest.json                            │
│ - trace_modules_manifest.json                              │
│ - etc.                                                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2: Run Metadata (Per-Run Aggregates)                 │
│ - pipeline_run_metadata.json                               │
│   • Aggregates all stage manifests                         │
│   • Run-level quality summary                              │
│   • Models used across all stages                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 3: Historical Registry (SQLite Table)                │
│ - pipeline_run_history table                               │
│   • Fast queries across all runs                           │
│   • Filter by model, quality, version                      │
│   • Links to full metadata files                           │
└─────────────────────────────────────────────────────────────┘
```

## Usage Examples

### Check Data Provenance

```python
from codrag.core import load_stage_manifest
from pathlib import Path

# Load augmentation manifest
manifest = load_stage_manifest(
    Path(".codrag/trace_augment_manifest.json")
)

print(f"Generated by: {manifest.model['model_name']}")
print(f"On: {manifest.finished_at}")
print(f"Quality: {manifest.quality['avg_confidence']}")
print(f"CoDRAG version: {manifest.codrag_version}")
```

### Aggregate Quality Metrics

```python
from codrag.core import aggregate_quality_metrics
from pathlib import Path

# Aggregate confidence scores from augmentation output
quality = aggregate_quality_metrics(
    Path(".codrag/trace_augmented.jsonl"),
    confidence_field="confidence"
)

print(f"Success rate: {quality['success_rate']}")
print(f"Avg confidence: {quality['avg_confidence']}")
print(f"Min/Max: {quality['min_confidence']} - {quality['max_confidence']}")
```

### Create Stage Manifest

```python
from codrag.core import create_stage_manifest, save_stage_manifest
from pathlib import Path
import time

# Create manifest at stage start
manifest = create_stage_manifest(
    stage_id="catalogue",
    run_id="run-abc123",
    project_id="proj-xyz"
)

# ... run stage logic ...

# Finalize manifest at stage end
manifest.finished_at = datetime.now(timezone.utc).isoformat()
manifest.elapsed_seconds = time.time() - start_time
manifest.quality = aggregate_quality_metrics(output_path)

# Save to file
save_stage_manifest(
    manifest,
    Path(".codrag/trace_augment_manifest.json")
)
```

## Benefits

### For Users

1. **Trust & Transparency**
   - See exactly which model generated each piece of data
   - Know when data was last updated
   - Understand data quality (confidence scores)

2. **Debugging**
   - "Why is this summary wrong?" → Check which model/version produced it
   - "Why did the pipeline fail?" → Check run history for error details
   - Identify files that consistently fail processing

3. **Quality Control**
   - See which runs had low confidence scores
   - Track quality improvements over time
   - Identify stale data that needs rebuilding

4. **Model Comparison**
   - Compare quality metrics across different models
   - Justify upgrading to a larger model
   - See which model works best for your codebase

### For Development

1. **Regression Testing**
   - Detect when code changes degrade quality
   - Compare metrics before/after prompt changes
   - Verify that new models improve results

2. **Performance Optimization**
   - Identify slow stages
   - Track throughput improvements
   - Optimize batch sizes based on historical data

3. **Support & Debugging**
   - Users can share run metadata for bug reports
   - Reproduce issues with exact model/version info
   - Identify patterns in failures
