# Structural Comparison and Logic Preservation

Before modifying any existing code, it is critical to establish a rigid verification strategy. This document outlines how we will perform a deep structural comparison to ensure 100% logic preservation during Refactor 2.

## The "Zero Logic Change" Rule
The primary mandate of this refactor is: **Move, don't modify.** 
No business logic, algorithms, conditionals, or API signatures may change. The only acceptable changes are to import paths and file locations.

## Verification Methodology per Target

### 1. `src/prep/core/trace.py` (2,460 lines)
**Current Structure:**
- 4 Data Classes (`TraceNode`, `TraceEdge`, `FileError`, `TraceBuildResult`)
- 3 Helper Functions (`_detect_language`, `_to_posix`, `_is_relevant`)
- 4 Analyzers (`PythonAnalyzer`, `SwiftAnalyzer`, `GenericRegexAnalyzer`, `JSAnalyzer`)
- 2 Core Classes (`TraceBuilder`, `TraceIndex`)
- 2 Entrypoint Functions (`build_trace`, `compute_trace_coverage`)

**Verification Protocol:**
1. Generate an AST dump or `grep` outline of all classes and methods in the original file.
2. After splitting into `models.py`, `analyzers/`, `builder.py`, and `index.py`, run an automated script (or `grep`) to map every original method to its new location.
3. **Crucial:** Ensure the `TraceIndex` graph structure remains unchanged. All 76 Python tests in `tests/test_trace*.py` must pass.
4. Ensure the `__init__.py` exposes exactly the same public interface as the original module.

### 2. `src/prep/api/routers/projects.py` (2,228 lines)
**Current Structure:**
- Project CRUD (`POST /projects`, `GET /projects`, `DELETE /projects/{id}`)
- Build Endpoints (`POST /projects/{id}/build`)
- Search/Context (`POST /projects/{id}/search`, `POST /projects/{id}/context`)
- Watcher (`POST /projects/{id}/watch/*`)
- Files (`GET /projects/{id}/files`)

**Verification Protocol:**
1. List all 30+ endpoints currently registered under the `@app.router` in this file.
2. After splitting into `crud.py`, `search.py`, `watch.py`, `files.py`, ensure every single path, HTTP method, and Pydantic request/response model is identical.
3. The OpenAPI schema (`/openapi.json`) generated by FastAPI before the refactor must exactly match the schema generated after the refactor. (We can save the JSON before and diff it).

### 3. `packages/ui/src/types.ts` (997 lines)
**Current Structure:**
- Over 150 exported interfaces and types spanning LLMs, Trace Graph, UI Layout, Config, and API schemas.

**Verification Protocol:**
1. Run `tsc --noEmit` on the entire monorepo before changes. It must pass.
2. After splitting into `types/models.ts`, `types/project.ts`, etc., ensure the `packages/ui/src/types/index.ts` barrel file exports everything.
3. Run `tsc --noEmit` again. The TypeScript compiler guarantees that no type definitions were lost or structurally altered. If a type is missing, the consuming component will immediately fail compilation.

### 4. `packages/ui/src/components/marketing/MarketingHero.tsx` (825 lines)
**Current Structure:**
- One giant component with a massive `switch` statement rendering 10 different JSX blocks.
- we should put these in a folder so the have their own unique location.
**Verification Protocol:**
1. Extract each `case` block verbatim into a new component file.
2. Run Vite build (`vite build`) and Storybook build (`npm run build-storybook`).
3. Visually verify the Marketing UI in development mode. The DOM structure (React component tree) should remain identical.

## Execution Guardrails
- **Pre-flight:** Capture the `wc -l` (line count) and method list of the target file.
- **Action:** Perform the split.
- **Post-flight Verification:** 
  - Run unit tests: `pytest tests/`
  - Run type checking: `npm run typecheck`
  - Run linting: `npm run lint`
- **Commit:** Commit *only* if all post-flight checks pass. If they fail, reset and analyze the missing logic.
