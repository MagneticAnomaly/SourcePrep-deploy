## What was done this session — GPL dependency replacement

### Problem

`pyproject.toml` declared `license = "MIT"` but the runtime imported
`igraph` (GPL-2.0) and `leidenalg` (GPL-3.0-or-later) in
`src/prep/core/cluster.py` for Leiden community detection. Both
libraries were installed ad-hoc in `.venv` and were not in
`pyproject.toml`. Publishing under Apache 2.0 with those imports in
the source tree was a license incompatibility — conservatively, an
acquisition-killing risk.

### Resolution

Replaced Leiden (`igraph` + `leidenalg`) with Louvain via `networkx`
(BSD-3-Clause), which is permissive and Apache-compatible. Scope was
narrower than the blocker doc suggested: one file
(`src/prep/core/cluster.py`), two functions
(`build_clusters_leiden` and `build_clusters_structural`).

Function signatures preserved — no callers needed updating. Both
functions were dormant in production (only the tag-based
`build_clusters` runs in the live pipeline), so the legal cleanup
was the primary win; algorithmic parity was the secondary verified-via-test
property.

## Known gotchas

### Venv `.pth` conflict (no longer present, but worth knowing)

The shared `.venv` had two competing editable-install `.pth` files:
- `_codrag.pth` (legacy, points at `/Volumes/4TB-BAD/HumanAI/CoDRAG/src`)
- `_editable_impl_prep.pth` (created when this session ran
  `pip install -e .` from the worktree, pointed at the worktree's src)

`_codrag.pth` wins by alphabetical sort, so pytest in the worktree
silently imported the **main repo's** `prep` package. This session
deleted `_editable_impl_prep.pth` to revert to the original config
and used `PYTHONPATH=src` to run worktree tests instead. Now that the
fix is merged to main, the legacy `_codrag.pth` resolves to the
updated code and the conflict is resolved.

If you ever see this pattern again: a worktree's tests appear to
pass without exercising the code change. Check `pip show prep` →
`Editable project location` and the `.pth` files in
`site-packages/`.

### P127-F2 line-number catalog brittleness

`tests/test_llm_direct_sites_hold_guarded.py` hardcodes line numbers
for each `llm.generate` call across `cluster.py`, `atlas/generator.py`,
`group_reasoning.py`, `concept_seeder.py`. Any edit to those files
that shifts lines will fail the F2 catalog test. After such edits:

```bash
grep -n "llm.generate" src/prep/core/cluster.py
# then update F2_SITES tuples in tests/test_llm_direct_sites_hold_guarded.py
```

### `build_clusters_leiden` name is now a misnomer

The function still bears the name `build_clusters_leiden`, but its
body is now Louvain. Renaming was deferred (would touch the test
import and any future external callers — currently zero in `src/`).
Tracked as a follow-up; not blocking.
