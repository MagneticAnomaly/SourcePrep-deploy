### NEW — Atlas reports "Stale" immediately after rebuild (becomes Part 11)

Dashboard screenshot 2026-05-17 (≈90 min after the rebuild finished)
showed atlas + all 10 sub-atlases badged "Stale" despite the rebuild
having completed successfully. Investigation:

```python
# src/prep/core/atlas/generator.py:1511-1521
def is_stale(self) -> bool:
    if not self.exists(): return True
    cs = self._resolve_changeset()
    if cs is None: return True
    return bool(cs.added) or bool(cs.modified) or bool(cs.deleted)
```

The check never compares `changeset.run_id` against the atlas's own
recorded `run_id`. Both artifacts carry `run-50071c9e0869` — the
atlas already consumed this changeset — but the staleness check sees
1971 entries in `changeset.added` and returns True.

Phase 135.5 introduced changeset-as-truth but did not wire the
"consumed" half of the contract. Likely co-affects other Phase 135.5
stages (deep_knowledge, group_reasoning, deepening, augmenter, etc.).

### NEW — Concepts panel reflects Part 09 symptom (not a separate bug)

Dashboard "Concepts" panel shows:
- 15 active+triage concepts (validated)
- **1795 Rationale / Seeds** — synthesis-fallback worker outputs
- **1334 questions pending** — same fallback
- **Module coverage 23/798 (2.9%)** — counts only validated concepts

This is *not* a separate bug. The `_calculate_coverage` API
(`src/prep/api/routers/concepts.py:75-121`) by design counts only
non-archived (active+triage) concepts toward coverage. Seeds bypass
the validator, so they don't move the coverage needle.

This is the **visible UI symptom of Part 09**: synthesis returns
empty → worker outputs save as seed → validator never sees them →
coverage stays low. Fixing Part 09 will lift coverage. No separate
Part needed.
