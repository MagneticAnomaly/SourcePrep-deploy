## FIX-16-1: `prep()` no-arg output is a firehose

**Impact:** High — contradicts the skill's own "refresh every 5 calls" guidance.
**Effort:** Medium — needs progressive-disclosure mode + tighter default budget.

### Observation
A single `prep()` call (no args, default budget) returned ~35,000 characters of structural context. The output enumerated 50+ named modules with multi-sentence rationales, then footnoted "Plus 193 smaller modules (2-4 files each), Plus 712 single-file modules."

This is genuinely useful **once**, but no agent can afford to call `prep()` a second time in the same session — the cumulative token burn is prohibitive. That directly conflicts with the guidance in `using-superpowers:prep` and CLAUDE.md that agents should re-call `prep` during long tasks to refresh structural context.

### Fix sketch
- Tighten default `max_chars` for the no-arg path; reserve the 35K-char output for explicit `verbose=true`.
- Add a `delta` mode that returns only what has changed since the last call in this session (requires session-scoped state on the daemon).
- Surface the top-N modules by relevance to the inferred task, not all 50+. The `task=` and `working_dir=` params already exist — make them the default behavior when the agent hasn't passed anything.

## FIX-16-2: Atlas section in CLAUDE.md is corrupted

**Impact:** High — committed garbage in the file every agent reads first.
**Effort:** Low for the cleanup, Medium for the root-cause fix in the generator.

### Observation
The `## Codebase Atlas` block at the bottom of `/Volumes/4TB-BAD/HumanAI/CoDRAG/CLAUDE.md` contains two distinct failure modes leaked into a committed file:

1. **LLM scratchpad leakage:** A meta-prompt fragment that begins "I need to write a concise project orientation header based on the provided data, following strict rules: plain text only, no markdown..." is embedded directly in the output. The model's internal planning text was treated as content.
2. **Degenerate token loop:** Thousands of repeated "加油" (Chinese: "keep going / add fuel") characters fill the rest of the section. This is a classic stuck-decoder pattern — the sampler fell into a low-entropy attractor and never escaped before the budget ran out.

Both failures originate in the atlas-generator LLM call. Neither is being detected before the output is written to disk and committed.

### Fix sketch
- **Immediate:** Hand-clean the corrupted Atlas section in CLAUDE.md so agents reading it stop loading garbage into their context. (Don't auto-regenerate yet — see next point.)
- **Generator hardening** in `src/prep/core/atlas/generator.py`:
  - Detect scratchpad leakage: reject outputs containing first-person planning text ("I need to write", "Let me parse", "I should") before persisting.
  - Detect degenerate loops: reject outputs where any single non-ASCII token repeats more than N times consecutively, or where Shannon entropy drops below a floor for a long span.
  - On rejection, retry with a different sampler config or fall back to a deterministic non-LLM atlas summary rather than persisting the bad output.
- Add a regression test that feeds known-bad LLM outputs (scratchpad-leak, repetition-loop) through the generator and asserts the bad output is **not** written.

## FIX-16-3: Module clustering produces near-duplicate top-level groups

**Impact:** Medium — confuses agents and inflates the atlas.
**Effort:** Medium — clustering / dedup pass on synthesized module names.

### Observation
The `prep()` output lists three separate top-level modules covering the same subject:

- **Agent Retrieval Benchmark & A/B Test Framework** (18 files)
- **Agent RAG Benchmarking Suite (Docs) #2** (7 files) — note the literal `#2` suffix
- **Agent RAG Retrieval Benchmark Suite** (7 files)

These describe the same subsystem at different file granularities. The `#2` suffix in the module name is itself a tell that the synthesizer hit a name collision and resolved it by appending a counter rather than merging.

A separate but related case: "CoDRAG Dashboard Frontend & State Management" and "Prep Dashboard Frontend Architecture" appear as distinct modules, which is partly the brand-drift issue but also partly a clustering miss — the same files are grouped under two names.

### Fix sketch
- Post-process synthesized module names: any name with a `#N` suffix should be flagged for merge review, not silently emitted.
- Add a name-similarity check (token overlap + embedding distance) across synthesized modules. Pairs above a threshold should either merge or escalate to a re-clustering pass.
- Surface "candidate-duplicate modules" in `prep_audit(action="scan")` so the user can see and approve merges.

## FIX-16-4: Module summaries read like consulting decks

**Impact:** Medium — slows agent comprehension; off-voice for the product.
**Effort:** Low to Medium — prompt-level fix.

### Observation
Representative module summary from the live output:

> Implements tiered security controls, cryptographic licensing, audit logging, and architectural governance for a local-first code intelligence product. Bridges enterprise policy enforcement (DLP, RBAC, secrets management) with consumer-grade privacy guarantees, while maintaining marketing transparency around security posture.

This is dense, abstract, and verb-heavy in a way that obscures what the code actually *does*. Agents have to re-read sentences to extract concrete entry points. It also conflicts with the project's own marketing-voice guidance: lead with plain-language outcomes, keep jargon as supporting detail.

The pattern repeats across most module summaries — "Bridges X with Y while Z," "Serves as the central nervous system for...," "Currently in active transition with critical gaps."

### Fix sketch
- Update the module-summary synthesis prompt to require:
  - First sentence: what an agent can *do* in this module (concrete verb + concrete object).
  - Second sentence: how it connects to the rest of the system.
  - Optional third sentence: caveats or in-flight work.
- Ban specific clichés in the prompt: "central nervous system," "bridges X with Y," "serves as the [foo] backbone," "currently in active transition."
- Add a post-generation lint pass that flags summaries exceeding ~40 words or containing the banned phrases, and re-prompts.
