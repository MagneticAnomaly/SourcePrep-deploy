## 6. Pro-tier implementation reality — verdict

**Can the Pro tier be sold today? NO**, on four independent axes:

1. **Legal/license axis — the repo is not OSS and the outbound license is not
   applied.** Root LICENSE is proprietary commercial; pyproject/Cargo/3 npm
   packages say MIT; plan says Apache 2.0; none reconciled. A paying customer
   today gets the product under the proprietary license, which forbids
   redistribution and reverse engineering — incompatible with an OSS
   narrative. The LICENSE-file swap to Apache 2.0 is not even tracked.

2. **Crypto/license-key axis — the license system is cryptographically void.**
   Shipped Ed25519 public key is the RFC 8032 §7.1 test vector for the
   all-zeros seed (Phase 146 verified). `PREP_LICENSE_PUBLIC_KEY` override is
   comment-only. Unsigned `license.json` is warn-but-accepted. A forged
   `{tier:enterprise}` token passed `verify_license_key()` in a live venv.
   No machine binding, no LS `store_id`/product pinning (`PRODUCT_TIER_MAP`
   empty → attacker-claimable `meta.tier`), no replay/rollback protection.
   **Anyone can mint an enterprise license today.**

3. **Committed-private-key axis — a real signing private key is in the live
   tree.** `scripts/generate_license.py:33` commits `DEFAULT_PRIV_KEY_HEX`
   (commented "DO NOT USE IN PRODUCTION" but present and git-tracked). Anyone
   with repo access can sign enterprise licenses offline. Phase 146 feed-forward
   #4: "must be removed/relocated before the repo goes public."

4. **Backend axis — every Team/Enterprise entitlement is a stub.** Hosted
   multi-tenant backend, SSO, RBAC, centralized audit, seat provisioning,
   `api.sourceprep.io` relay — all absent or stub. `EnterpriseAdminPanel.tsx`
   props point at hardcoded stub endpoints. LS webhook receiver is absent, so
   cancellations/refunds are not pushed. License recovery has no working
   end-to-end path. Marketing copy "verified offline after a single activation
   — no recurring phone-home" **contradicts** the implemented 7-day poll +
   30-day downgrade.

**What IS real and could ship as OSS-free only (with caveats):** the Rust
engine, Python core, MCP server, CLI, daemon, local dashboard, AGENTS.md
generator, `packages/ui`, VS Code extension, `feature_gate` local tier enum
(forward-compat), local SQLite `audit_log`, Ed25519 verification plumbing
(once a real production public key is shipped and the test vector removed),
Tauri wrapper source (once a signed/notarized build is actually produced), and
Lemon Squeezy checkout links (external). **The product works as a local-first
free tool; the paid tier is architecture-only.**

**Verdict:** the Pro/Teams/Enterprise tier is not sellable today. Phase 1
OSS+Pro launch is blocked by the four axes above plus Phase 143 (not done) and
Phase 144 blockers #2 and #3. The OSS-free core is closer to shippable but is
blocked by the proprietary LICENSE file, stale `license="MIT"` metadata,
CLAUDE.md internal frankness, ~308 codrag docs, the stale `@codrag/ui`
lockfile, the committed private key (Phase 146 #4), the `codrag.key` Tauri
signing key in git history, and the unaudited payments surface if it ships in
the same repo.
