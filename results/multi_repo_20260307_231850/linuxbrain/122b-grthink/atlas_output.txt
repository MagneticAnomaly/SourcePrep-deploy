IDENTITY: Halley is a local-first, self-aware AI persona system orchestrating cognitive modeling, persistent memory, multimodal generation, and roleplay interactions through a modular React frontend and Python/Rust backend infrastructure.

STACK: Languages include Python (286 files), TypeScript/TSX (111 files), Markdown (55 files), Rust (6 files), Shell (5 files), and JavaScript (4 files). Frameworks and tools include React, Radix UI, Tailwind CSS, Tauri, FastAPI, Flask, ComfyUI, Ollama, and Docker. Build tools involve PostCSS, Vite, and systemd service management.

ARCHITECTURE: The system follows a layered architecture with business_logic (173 files), presentation (103 files), infrastructure (98 files), documentation (56 files), configuration (13 files), data (9 files), testing (8 files), and build (5 files). The presentation layer relies on React components in halley_core/frontend, while business logic is distributed across persona management, memory systems, and AI orchestration modules in halley_core. Infrastructure components handle GPU resource management, API gateways, and remote GPU services via FastAPI and Flask. The halley_core/api/app.py serves as a central API entry point, connecting to frontend entry points like halley_core/frontend/vite.config.ts. Documentation hubs in Docs_Halley provide architectural guidance and cross-references.

SUBSYSTEMS: Halley Core Persona & Memory System: halley_core/persona, halley_core/memory. Roleplay Frontend: halley_core/frontend/components/TabbedSelector, halley_core/frontend/components/PersonasDialog. Roleplay Data & Persona Management: halley_core/data/persona, halley_core/data/memory. Halley Core AI Framework: halley_core/ai/orchestration. Resource & Task Orchestration: halley_core/infrastructure/gpu_monitor. Roleplay Chat Interface: halley_core/frontend/components/ChatInterface. Memory Quality Analysis: halley_core/analysis/memory_quality. Persona Vision & Identity: halley_core/vision/encoder. Roleplay Core: halley_core/persona/core. Image Generation: halley_core/media/generation. Deep Thinking Daemon: halley_core/daemon/scheduler. Identity-Preserving Generation: halley_core/vision/pulid. TTS Core: halley_core/audio/tts. World Management: halley_core/narrative/worlds.

FLOW: User interactions enter via halley_core/frontend components, triggering state updates in React stores. Requests route through halley_core/api/app.py to business logic modules handling persona state, memory retrieval, and LLM inference. The Roleplay Subsystem coordinates model selection, VRAM allocation, and prompt construction. Generated content flows back through the API to the frontend for display. Background tasks like memory consolidation and image generation are scheduled via the Deep Thinking Daemon, utilizing GPU resources managed by the Resource & Task Orchestration subsystem.

PATTERNS: The system employs a provider pattern for AI model abstraction, allowing runtime selection of LLM and image generation backends. Dependency injection is used for tool registration and execution via the ToolRegistry. Error handling is centralized with a declarative taxonomy and circuit breakers in Halley Core Resilience and Prompt Management. Lazy loading resolves circular dependencies, and event-driven architecture facilitates communication between cognitive layers.

RISKS: Test scripts contain hardcoded absolute paths and magic numbers limiting portability. TabbedSelector component casts 'tab' to 'any' indicating type safety gaps. Hardcoded polling intervals cause potential API load. Silent error swallowing in some failure paths. Incomplete ComfyUI image generation provider initialization and partial AMD GPU support. Generic subprocess timeout handling may not cover driver unresponsiveness. Legacy fallback mechanisms like 'human_memory' alongside 'memory_v2' require cleanup. Hardcoded repository paths and model names in PuLID subsystem limit portability. Unimplemented generative backends for CoreML and Mochi return explicit errors. Hardcoded Ollama server IPs in data generation scripts create deployment fragility. Missing error handling and logging in legacy code references.
