IDENTITY: Halley is a local-first AI persona system orchestrating cognitive modeling, persistent memory, and multimodal generation for immersive roleplay interactions without cloud telemetry.

STACK: Languages include Python (286 files), TypeScript/TSX (111 files), Rust (6 files), and Shell (5 files). Frameworks encompass React, Radix UI, Tailwind CSS, FastAPI, Flask, Tauri, and Ollama. Build tools involve Vite, PostCSS, and systemd. Runtime supports Windows, macOS, and Linux with GPU acceleration via CUDA and AMD ROCm.

ARCHITECTURE: The system follows a layered architecture separating business logic (173 files), presentation (103 files), and infrastructure (98 files). The halley_core/api/app.py serves as the central API gateway connecting frontend components like halley_core/frontend/vite.config.ts to backend services. Business logic modules handle persona cognition and memory persistence, while presentation layers manage UI primitives and chat interfaces. Infrastructure components orchestrate GPU resources, model loading, and remote execution via RunPod or local Docker. Data flows from user input through the Roleplay Chat Interface to the Halley Core AI Framework, which routes requests to specific cognitive or generative subsystems.

FLOW: User input enters via halley_core/frontend/components/Chat.tsx, triggering the Roleplay Chat Interface which routes to halley_core/api/app.py. The API dispatches to the Halley Core AI Framework for cognitive processing, invoking halley_core/cognitive/event_bus.py for belief tracking and halley_core/memory/v2/semantic_search.py for memory retrieval. Context is compressed via halley_core/compression/claRa_service.py before being sent to the OllamaProvider in halley_core/providers/ollama_provider.py. Generated responses flow back through the error handling layer in halley_core/error/error_mapper.py to the UI. Image generation requests are routed to halley_core/generation/image_provider.py, which coordinates with ComfyUI or local Diffusers. GPU resource management is handled by halley_core/infrastructure/gpu_monitor.py, ensuring VRAM constraints are respected.

PATTERNS: The system employs a provider pattern for LLM and image generation backends, allowing runtime selection via halley_core/providers/llm_adapter.py. Dependency injection is used for tool registration in halley_core/tools/tool_registry.py. Error handling is centralized in halley_core/error/error_mapper.py, mapping technical exceptions to persona-styled recovery messages. Lazy loading resolves circular dependencies in the Halley Core AI Framework. Event-driven architecture facilitates communication between cognitive layers via halley_core/cognitive/event_bus.py.
