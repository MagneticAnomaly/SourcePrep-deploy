IDENTITY: DebateHaus is a marketing site for a video-first debate platform featuring scroll-driven GSAP animations, parallax effects, and conversion-focused landing pages.
STACK: Next.js, React, TypeScript, Tailwind CSS, GSAP, ScrollTrigger, ESLint, SWC, PostCSS, Autoprefixer.
ARCHITECTURE: The system comprises four layers: presentation (25 files), configuration (9 files), documentation (9 files), and infrastructure (1 file). The presentation layer relies on configuration artifacts like tsconfig.json and .eslintrc.json for type safety and code quality. Documentation in docs/DesignPlan/1-hero.md guides the implementation of visual components. The root layout in src/app/layout.tsx initializes global styles and integrates the Inter font.
SUBSYSTEMS: Ui (Src): src/app/layout.tsx, src/components/EnhancedHero.tsx, src/components/BetaSignupForm.tsx, src/components/PercentageBasedRoadmapSection.tsx, src/components/CanvasBackground.tsx. Ui (Docs): docs/DesignPlan/1-hero.md, docs/questions_for_designer.md. Ui (Public): public/copy.json. Ui (Config): tsconfig.json, .eslintrc.json, next.config.js, package.json.
FLOW: Requests enter via src/app/layout.tsx which loads global styles and metadata. The Ui (Src) subsystem orchestrates scroll-driven animations using src/hooks/useGSAP.ts to manage GSAP instances. Content is fetched synchronously via src/hooks/useCopy.ts from public/copy.json. The BetaSignupForm.tsx handles user acquisition logic, rendering modals based on global state.
PATTERNS: The system uses custom hooks like useGSAP.ts and useCopy.ts for centralized state and animation management. Global singletons manage animation state instead of React Context. Content is decoupled from code via JSON assets.
RISKS: Ui (Src) contains legacy files with _OLD and _BAD suffixes still exported. Production debug logging exists in the Trust section. ScrollTrigger cleanup relies on iteration rather than instance storage. Global animation state uses mutable singletons risking race conditions. BetaSignupForm.tsx uses simulated API calls with setTimeout, hardcoded animation timings, and console.log statements. Ui (.) #4 has hardcoded utility classes with !important overrides and redundant style definitions. Ui (Docs) #4 has chronological regressions in roadmap timelines and duplicate date assignments.
