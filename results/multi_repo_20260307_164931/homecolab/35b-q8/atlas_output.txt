IDENTITY: HomeColab is a collaborative real estate search platform for iOS and web that ingests property data via CSV and URL parsing, validates pricing with CMA logic, and renders 3D comparison matrices for agents and clients.
STACK: Languages include Swift, TypeScript, JavaScript, and Markdown. Frameworks are SwiftUI, React, Next.js 14, React Three Fiber, Framer Motion, and Firebase. Build tools are Xcode, Swift Package Manager, and Node.js. Runtime environments are iOS, Web, and Cloud Functions.
ARCHITECTURE: The system follows a layered architecture with documentation (282 files) and presentation (202 files) dominating the codebase. Core business logic resides in 45 files, supported by 20 configuration and 17 infrastructure files. The architecture bridges a legacy single-partner model to a Shared Core, Separate Apps strategy via the HomeColabShared Swift Package. Data flows from ingestion modules like Real Estate Data Ingestion and Normalization to the monolithic FirestoreManager.swift which acts as the central hub with 64 incoming edges. The UI layer relies on DesignSystem/Colors.swift and Components/UnifiedListingCard.swift for rendering. The web presence uses Next.js with a marketing site and support portal, while the mobile app uses SwiftUI with a Share Extension for data ingestion.

FLOW: User onboarding initiates via HomeColabApp.swift, routing to Ios (Homecolabapp) for authentication using Google and Apple OAuth. Property data enters through Real Estate Data Ingestion and Normalization, where LinkPreviewManager parses URLs or CSV files are uploaded. Data flows to FirestoreManager.swift for storage and validation against CMA rules. The UI layer renders this data using Components/UnifiedListingCard.swift and Spatial Visualization & Comparison Matrix for 3D views. Collaboration features sync state via HomeColab Collaboration & Partner Linking, utilizing Firestore for real-time updates. Monetization logic in HomeColab Ad Monetization Subsystem checks feature flags before rendering ads. The web marketing site uses Next.js components from HomeColab UI Components and Sections to display landing pages.
PATTERNS: The system uses a monolithic FirestoreManager.swift for data access, violating Single Responsibility. Dependency injection is limited, with heavy reliance on singletons like PropertyEditorModeManager. Error handling is inconsistent, with some areas using force unwraps and others using AppError enumerations. State management varies between SwiftUI state, Zustand stores for 3D dashboards, and in-memory chat stores. The architecture employs a Shared Core Swift Package to decouple logic between Consumer and Business apps.
RISKS: Critical technical debt includes monolithic components (FirestoreManager, UnifiedListingCard) violating Single Responsibility. Hardcoded feature flags and missing crash reporting exist in the iOS core. Insecure Firestore rules allow unauthorized updates. The advertising layer lacks GoogleMobileAds SDK integration. The collaboration sync logic risks infinite loops due to timestamp mismatches. Legacy LinkPresentation framework usage requires migration to UnifiedListingCard. Mock data reliance in web components prevents real-time backend integration. Deprecated singleton PropertyEditorModeManager is scheduled for removal. Hardcoded agent IDs limit dashboard reusability. The logging infrastructure mixes legacy print statements with planned os.log migration. Placeholder App Store links exist in marketing configuration. Incomplete SKAdNetwork identifier lists hinder monetization. Documentation contains future-dated timestamps and missing implementation targets.
