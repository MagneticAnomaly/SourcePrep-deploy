IDENTITY: HomeColab is a collaborative real estate search platform for iOS and web that enables agents and clients to share property data, vote on listings, and visualize comparisons via 3D matrices.
STACK: Languages include Swift (139 files), TypeScript/JavaScript (159 files), Markdown (284 files), and Shell scripts (3 files). Frameworks are SwiftUI, React, React Three Fiber, Next.js 14, Framer Motion, and Firebase. Build tools include Xcode, Swift Package Manager, and Netlify. Runtime environments cover iOS 15+, macOS, and serverless cloud functions.
ARCHITECTURE: The system follows a layered architecture with documentation (282 files) and presentation (202 files) dominating the codebase. Core business logic resides in 45 files, supported by 20 configuration and 17 infrastructure files. The architecture bridges a legacy single-tenant model to a dual-app ecosystem via a Swift Package named HomeColabShared. Central hubs include Managers/FirestoreManager.swift and App/HomeColabApp.swift. The Data Ingestion subsystem orchestrates CSV parsing and URL extraction, feeding into the Core & Collaboration Architecture which manages Listing and SharedSpace models. The Design System provides tokens via DesignSystem/Colors.swift. The Spatial Visualization layer uses React Three Fiber for 3D rendering, while the Marketing Landing Page uses Next.js for static generation.

FLOW: User onboarding begins at App/HomeColabApp.swift, routing to HomeColabOnboard/Entry.swift for platform detection. Authentication flows through HomeColabAuth/OAuth.swift to Firebase/firestore.rules. Property ingestion starts at HomeColabIngestion/Parser.swift, normalizing data via HomeColabIngestion/Normalizer.swift. Comparison views render via HomeColabCompare/CompareView.swift, utilizing HomeColab3D/HeartAnimation.swift for 3D elements. Collaboration syncs state through HomeColabCollaboration/SyncManager.swift. Monetization logic executes in HomeColabAds/AdCoordinator.swift. Error handling is centralized in HomeColabBuild/AppError.swift, logging to Crashlytics.
PATTERNS: Dependency injection is implied via the HomeColabShared Swift Package for shared logic. Error handling uses a unified AppError enumeration in HomeColabBuild/AppError.swift. State management relies on Zustand stores in HomeColabMatrix/StateStore.swift and singletons like FirestoreManager.swift. Feature flags are migrating from static Swift constants to Firebase Remote Config via HomeColabFlags/RemoteConfig.swift.
RISKS: Critical technical debt includes monolithic 'god object' components (FirestoreManager, UnifiedListingCard) violating Single Responsibility. Security vulnerabilities exist in Firestore invite rules (lack of rate limiting, weak UUIDs). The advertising layer relies on stubbed GoogleMobileAds SDK integration. Deprecated LinkPresentation framework usage in ListRowView requires migration. Infinite loop risks exist in FirestoreManager+Sync due to timestamp mismatches. Hardcoded feature flags and missing crash reporting hinder production stability. Documentation inconsistencies and missing implementation targets create traceability gaps.
