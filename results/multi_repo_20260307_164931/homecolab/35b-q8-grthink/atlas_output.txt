IDENTITY: HomeColab is a collaborative real estate search platform for iOS and web that ingests property data via CSV and URL parsing, validates pricing through CMA logic, and renders 3D comparison matrices for agents and clients.
STACK: Languages include Swift, TypeScript, JavaScript, and Markdown. Frameworks are SwiftUI, React, Next.js 14, React Three Fiber, Framer Motion, and Firebase. Build tools involve Xcode, Swift Package Manager, and shell scripts. Runtime environments are iOS and Node.js.
ARCHITECTURE: The system follows a layered architecture with documentation (282 files), presentation (202 files), business logic (45 files), configuration (20 files), infrastructure (17 files), data (8 files), testing (8 files), and build (5 files). Core modules connect via FirestoreManager.swift which acts as a central hub with 64 incoming edges. The HomeColabApp.swift entry point (52 incoming edges) orchestrates the iOS lifecycle while UnifiedListingCard.swift (50 incoming edges) manages property rendering. The Data Ingestion subsystem feeds into the Core & Collaboration Architecture which bridges legacy single-partner models to a multi-tenant 'Shared Core, Separate Apps' strategy. The Marketing Landing Page and Web Presence subsystems handle user acquisition and SEO via Next.js routes.

FLOW: User onboarding begins at HomeColabApp.swift which initializes Firebase and routes to the onboarding flow. Property data ingestion occurs via Property Listing Ingestion Subsystem using CSV parsing and URL extraction, normalizing data in Real Estate Data Ingestion and Normalization. The UnifiedListingCard.swift component renders this data, triggering the 3D visualization in Ios 3D Visualization Dashboard via React Three Fiber. Collaboration state is synchronized through FirestoreManager.swift, which listens to changes in HomeColab Collaboration & Partner Linking. Monetization logic in HomeColab Ad Monetization Subsystem checks feature flags in Feature Flags and Debug Infrastructure to display ads. Legal compliance is enforced by Legal Compliance & Data Enrichment which validates data provenance before rendering.
PATTERNS: The system uses a centralized Design System (DesignSystem/Colors.swift) for visual consistency across iOS and web. Dependency injection is implied through the use of Swift Packages like HomeColabCore for shared logic. Error handling is standardized via AppError enumeration in Ios (Homecolabapp) #35. State management relies on Zustand stores for web dashboards and SwiftUI state for mobile views. The architecture employs a Strangler Fig pattern for migrating monolithic components like FirestoreManager.
RISKS: Critical technical debt exists in the monolithic FirestoreManager and UnifiedListingCard components violating Single Responsibility. The advertising layer lacks GoogleMobileAds SDK integration and contains placeholder views. The collaboration subsystem risks infinite loops in FirestoreManager+Sync due to timestamp mismatches. The core architecture has incompatibilities between the 1:1 user-to-space model and Business App multi-user requirements. Hardcoded mock data in web components prevents real-time backend integration. Deprecated LinkPresentation framework usage in ListRowView requires migration to UnifiedListingCard. Security vulnerabilities include insecure Firestore rules allowing unauthorized updates and exposed API keys in Info.plist. Missing crash reporting and incomplete data clearing on sign-out are critical stability risks. The logging infrastructure contains legacy print statements and commented-out Crashlytics integration.
