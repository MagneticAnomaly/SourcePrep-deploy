IDENTITY: HomeColab is a collaborative real estate search platform enabling agents and clients to share, compare, and rank property listings via iOS and web interfaces using Firebase backend services.
STACK: Languages include Swift, TypeScript, JavaScript, Markdown, and Shell. Frameworks encompass SwiftUI, React, React Three Fiber, Next.js, Framer Motion, and Lucide. Build tools involve Xcode, Swift Package Manager, and Next.js CLI. Runtime environments cover iOS 15+, Web Browsers, and Node.js.
ARCHITECTURE: The system follows a shared core strategy decoupling reusable logic into HomeColabCore Swift Package while maintaining separate Consumer and Business App entry points. Major layers include Documentation (282 files), Presentation (202 files), Business Logic (45 files), Configuration (20 files), Infrastructure (17 files), Data (8 files), Testing (8 files), and Build (5 files). The architecture bridges native mobile functionality with web-based acquisition via a Next.js marketing site and support portal. Core data models like Listing and SharedSpace reside in HomeColabCore, synchronized via FirestoreManager.swift. The presentation layer utilizes a design system defined in DesignSystem/Colors.swift and Components/UnifiedListingCard.swift.

FLOW: User interactions begin at App/HomeColabApp.swift or marketing site entry points, routing through Views/Queue/QueueView.swift for property discovery. Data ingestion occurs via Real Estate Data Ingestion and Normalization subsystems parsing URLs or CSVs, validated by CMA logic, then persisted to Firestore via Managers/FirestoreManager.swift. Collaborative features synchronize state through Firestore rules defined in Firebase/firestore.rules, updating UI components like Components/UnifiedListingCard.swift. 3D visualizations in Spatial Visualization & Comparison Matrix render data using React Three Fiber. Monetization logic in HomeColab Ad Monetization Subsystem controls ad display based on user context.
PATTERNS: The system employs a Shared Core, Separate Apps architecture using HomeColabCore for decoupled logic. Dependency injection is managed via singleton state managers like FirestoreManager.swift. Error handling utilizes a unified AppError enumeration in Ios (Homecolabapp) #35. Design consistency is enforced through DesignSystem/Colors.swift and centralized content configuration. State management relies on Zustand stores for web and SwiftUI state for iOS.
RISKS: Critical migration required for ListRowView to replace deprecated LinkPresentation with UnifiedListingCard. Significant reliance on hardcoded mock data in web comparison components prevents real-time backend integration. Brittle URL parsing logic and missing type definitions in activity feeds require refactoring. GoogleMobileAds SDK not yet integrated; placeholder views and commented-out code must be configured. Monolithic FirestoreManager and UnifiedListingCard violate Single Responsibility principle. Hardcoded feature flags and missing crash reporting exist. FirestoreManager+Sync contains risk of infinite loops due to timestamp mismatches. 1:1 user-to-space Firestore model blocks multi-project management. Legacy print statements and deprecated utilities coexist with planned os.log migration. Deprecated singleton PropertyEditorModeManager scheduled for removal. Incomplete SKAdNetwork identifier list and missing GDPR/CCPA UMP SDK implementation. Performance concerns with over 50 HTML elements in 3D scenes. Exposed API keys in Info.plist and missing Firebase App Check.
