IDENTITY: HomeColab is a collaborative real estate search platform enabling agents and clients to share, compare, and rank property listings via iOS and web interfaces while managing data ingestion, monetization, and legal compliance.

STACK: The ecosystem utilizes Swift and SwiftUI for native iOS development, React and Next.js for web interfaces, and Firebase for backend services including Firestore, Cloud Functions, and Authentication. Build tools include Xcode for mobile and standard Node.js tooling for web. Languages include .md, .swift, .tsx, .js, .ts, and .sh.

ARCHITECTURE: The system follows a 'Shared Core, Separate Apps' strategy transitioning from a monolithic structure. The HomeColabCore Swift Package decouples reusable logic. The presentation layer spans iOS Views and React components, interacting with a serverless Firebase backend. Key entry points include App/HomeColabApp.swift for iOS and various Next.js pages for web. Data flows through Managers/FirestoreManager.swift which currently acts as a monolithic hub, violating single responsibility. The DesignSystem/Colors.swift and Components/UnifiedListingCard.swift serve as central visual anchors.

FLOW: User actions in Views/Queue/QueueView.swift trigger state updates managed by Managers/FirestoreManager.swift. Data persists to Firebase/firestore.rules governed by security rules. Ingestion occurs via HomeColabShare/ShareViewController.swift parsing URLs or CSVs. The App/HomeColabApp.swift initializes the environment and routes to specific views. Marketing content loads from centralized configuration files. 3D visualizations render via Components/UnifiedListingCard.swift using React Three Fiber.

PATTERNS: The codebase relies heavily on Managers/FirestoreManager.swift as a central state hub, creating coupling. DesignSystem/Colors.swift enforces visual consistency. Error handling is standardized via AppError enumeration in Ios (Homecolabapp) #35. Barrel exports centralize component APIs.

RISKS: Critical migration required for ListRowView to replace deprecated LinkPresentation. Significant reliance on hardcoded mock data in web comparison components prevents real-time backend integration. Brittle URL parsing logic and missing type definitions in activity feeds require refactoring. GoogleMobileAds SDK not yet integrated; placeholder views and commented-out code must be configured. Monolithic 'god object' components (FirestoreManager, UnifiedListingCard) violate Single Responsibility. Hardcoded feature flags and missing crash reporting exist. Insecure Firestore rules allow unauthorized updates. FirestoreManager+Sync implementation risks infinite loops due to timestamp mismatches. Current 1:1 user-to-space Firestore model incompatible with Business App multi-user requirements. Logging infrastructure contains legacy print statements and commented-out Crashlytics integration. Deprecated singleton PropertyEditorModeManager scheduled for removal. Hardcoded agent ID limits dashboard reusability. Uncommitted duplicate file artifact in dashboard module. Missing 'TODO_Legal_Ops' document and undefined storage strategy for server-side vector store. Stubbed AdMob implementations with missing dependency imports and unconfigured App IDs. Performance concerns with 50+ HTML elements in 3D scene. Inconsistent state update timing in dashboard persistence. Missing memoization causing performance bottlenecks. Hardcoded and exposed API keys in Info.plist. Missing Firebase App Check and unencrypted sensitive data storage. Stubbed App Tracking Transparency code. Missing VoiceOver labels and unverified Dynamic Type. Incomplete testing coverage for core logic and Firestore rules. Dead code and legacy components in Property Workspace. Future-dated placeholders in legal documents. Safety locks preventing standard link previewer functionality for real estate domains.
