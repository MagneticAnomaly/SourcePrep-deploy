IDENTITY: This project is a multi-platform codebase integrating SQLModel database operations, Rust-based code analysis, and React/TypeScript UI components for the CoDRAG system and Halley chat applications.

STACK: The codebase utilizes Python with SQLModel and FastAPI for backend persistence, Rust for CLI tools and code analysis engines, TypeScript and React for web interfaces, Kotlin for Android, and Swift for iOS networking. Build tools include Vite, Maturin, and various CI/CD pipelines for cloud deployment on Google Cloud Run, Modal, and RunPod.

ARCHITECTURE: The system is organized into seven layers: testing (1814 files), documentation (1267 files), business_logic (1082 files), presentation (782 files), infrastructure (477 files), configuration (476 files), and build (65 files). The presentation layer relies heavily on TEST2/website.clean/app/layout.tsx and TEST2/website.clean/components/sections/HeroSection.tsx as central hubs. The business logic layer connects SQLModel Database Integration with UI and Backend Integration Subsystem, while the infrastructure layer supports HTTP/2 Client Implementation and UI and Network Caching Subsystem. Data flows from CLI Tools and Text Processing through the Code Analysis Engine to the UI and Search Subsystem.

FLOW: Requests enter through TEST2/website.clean/app/layout.tsx which routes to specific pages like TEST2/website.clean/app/download/page.tsx or TEST2/website.clean/app/privacy/page.tsx. The UI renders components from TEST2/website.clean/components/sections/HeroSection.tsx and TEST2/website.clean/components/sections/Footer.tsx. Backend operations utilize SQLModel Database Integration for CRUD tasks, while code analysis flows through Code Analysis Engine (Rust with Python Bindings) to generate insights displayed in Trace UI Visualization System. Data serialization occurs in UI and Data Serialization Subsystem before being cached by UI and Network Caching Subsystem.

PATTERNS: Shared dependencies include website-ui, website-legal, website-content, and legal-docs across nearly all subsystems. Error handling is standardized in UI Error Handling and Exception Management using HTTP status codes and custom exceptions. Testing is pervasive with dedicated infrastructure for SQLModel, Kotlin, and general mocking frameworks.
